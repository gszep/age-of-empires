# Project post-mortem — 2026-10-01

## Verdict and method

**A substantially more capable game shipped, and verification improved. The
largest remaining failures are incorrect acceptance criteria, fragile unattended
execution, and integration/deployment work outrunning operational safeguards.**
The previous review's central lesson still applies, with a qualification:
structural safeguards help only when they run in the active harness and test the
right condition.

The last project-wide post-mortem was [September 19](2026-09-19.md). The September
23 performance report and September 24 feedback review were narrower reviews.
This review covers every delivery checkpoint after the previous review's
implementation/handoff, **`700679a..1ad7dcf`**, September 19–October 1. Its eight
same-day review/remediation commits (`f834ac9..700679a`) are the baseline whose
recommendations are evaluated, rather than counted again as subsequent delivery.

Method: three chronological audits, cross-checked against git history/diffs,
GitHub issue discussions, original Claude and OpenCode session/tool records,
maintained evidence documents and surviving local logs. The coordinating audit
independently checked metrics, current gate/configuration, test changes and stale
documentation. Unlike the previous review, this is **not a claim to have read
every tool-output line in every session**. The entire commit range was inventoried;
causal findings use targeted primary evidence. No new runtime tests, imports or
service changes were made. Historical green results are identified as such.

## 2. What worked

### Outcome-based verification became normal

The September review found damage tests replaced by rule-table assertions and
buttons untested despite green simulation tests. This period routinely measured
actual payments, damage, food deposits, training/research completion, ownership,
JSON continuation and real button/key actions. Separate owned/fallback probes
became common.

The gates caught genuine integration mistakes: disabled Carrack effects leaking
into Briton warships, incorrect availability aliases, production-speed omissions,
Petard contact behavior, missing Heresy typing, recipient research on captured
factories and firearm-to-melee switching. These are successes of verification,
not evidence that every failed development run was wasted.

### The best debugging reduced failures to their actual cause

The texture-residency work initially caused animation churn and a rendering
failure. An outline-only hypothesis did not solve it. The later investigation
captured the failing sampler and reduced it to **A → B → dispose A → create
another B-rendering object**. Texture-lifetime cache keys fixed the reproduced
failure. Earlier failed runs remained explicitly failed evidence (#172,
`d1edf32`, `tools/sampler_residency_fixture.ts`).

The block-compression investigation similarly separated a real RGB565 endpoint
bug from permitted hardware interpolation instead of tuning to one GPU. Production
remained PNG. Terrain crossing checks failed at 0.030495; source shader bindings
identified incorrect anisotropy, and the unchanged check then measured 0.001896.
The failing number was not overruled by a plausible picture.

### Sustained evidence and tradeoffs were reported more honestly

The [September 23 report](2026-09-23-performance.md) records:

- Three 12,000-tick simulation runs: **50.087 → 34.025 seconds**, matching state
  hashes in the checked traces.
- Ten-ship estimated RGBA sprite residency: **3.88 GB → 0.875 GB**, identical
  rendered pixels, GPU texture count 128 → 65.
- A **156.67-minute** clean browser run, 156 samples and zero invalid bindings.

It also records a **3,329.88 MiB** peak sprite estimate, pending body pages in
three samples, and remaining Windsor 10× spikes (#175). The nominal 512 MiB
budget was accurately described as soft, not total RSS or a hard GPU limit.

Audio evidence likewise distinguished a 27-track natural music cycle from a
39-minute combined soak. The latter completed 19 rounds, all at tick limits;
that does not prove AI finishing power. The music-only run disabled scene redraws.
Neither software-rendered soak establishes physical-GPU gameplay FPS.

### Source investigation sometimes prevented an incorrect feature

The proposed sheep-follow behavior was challenged before shipping; the human
clarified AI return-to-TC behavior and the implementation used public move orders
(#136). Corrupt monk sources were diagnosed with exact container walks and hashes
instead of weakening the decoder (#247/#119). RMS includes exposed incorrect
Black Forest clearings and Islands assumptions. Audio inspection found complete
streams and multi-action events omitted by earlier assumptions.

This is a meaningful improvement over treating remembered behavior or a failed
first search as reference evidence.

## 3. What did not work

### A. A passing test still too often proved the wrong expectation

This is the most important recurring quality failure.

| Case | What initially passed | What was actually wrong |
| --- | --- | --- |
| Foam #89 | Smooth crest-position statistic | Texture discontinuity at the wrap was five times other frame steps; several follow-ups needed human correction |
| Tree fog #88 | Late shadow-texture binding test | Ground fog still cut through opaque crowns; the human rejected the first fix |
| Feedback #58 | General gate and dedicated browser smoke | HUD teardown could delete units; background vanished at stable opacity |
| Cursor #239 | Browser explicitly expected a flag on TC selection | Flag should be armed only through the gather-point action |
| Converted mobile cargo #178 | Tests accepted recursive passenger conversion | Human clarified passengers retain owners and only carrier owner ejects |
| Terrain plants #250 | Placement/fog/pixel-change checks | Owned shadow layers were present but not drawn |

The #58 lifecycle/background defects were corrected **before** its first commit;
they were premature acceptance claims, not proven shipped regressions. The wrong
parchment source did ship and required native WPFG/XAML discovery after the human
provided captures. See [the detailed review](2026-09-24-issue58.md).

The tree correction illustrates the right change in observable: before the final
fix, revealing ground changed all 620 sampled opaque canopy pixels; afterwards,
none changed. That measures the reported defect. Testing a nearby loading race
did not.

**Analysis:** more browser coverage helps only after the expected behavior and
observable are independently justified. Several implementation and test pairs
agreed with each other and were both wrong. The human remained the independent
acceptance evaluator.

### B. Four long autonomous mandates failed to use their authorised windows

| Run | Observed interruption | Attribution |
| --- | --- | --- |
| September 20–21, eight hours | External-directory approval stayed pending **8h01m49s**, beginning about 42 seconds after start | Readiness was promised without testing the live harness's required permissions |
| September 24–25, civilisation run | Explicit usage-limit error about **5h43m** after start | Quota exhausted; starting quota and exact workstream costs are unknown |
| September 28–29, twenty hours | Explicit 429 usage-limit error about **3h19m** after start | Franks/Goths shipped; Teutons unfinished; later human instruction narrowed continuation |
| September 30–October 1, eight hours | Unfinished provider request from **23:21:46Z to 07:25:44Z** | No completed patch arguments; ended on human cancellation; precise transport trigger unproven |

The first and fourth consumed essentially whole overnight windows. They must not
be mislabeled as slow implementation or a shell tool running for eight hours.
The Japanese run produced no checkpoint and never reached its planned #113 work;
completion followed a new instruction the next morning.

The permission preflight and ten-minute provider-request deadline are useful
structural repairs. Controlled timeout fixtures demonstrate the idle-watchdog gap
and total-request bound without killing a healthy long local tool. But the latter
is **per request**: retries can extend the turn, and there is no demonstrated
end-to-end run supervisor guaranteeing useful progress or deadline completion.
Context grew to 642,881 tokens in the Chinese session with substantial pre-tool
latency; this does not prove context caused the earlier stalled stream.

Sources: OpenCode sessions `ses_f3ef9a963ffemHhvpLlUb7OEmd`,
`ses_f2aa005b4ffeXFgcG4HPy50wEg`, `ses_f1638e43effezLFTek14qcgZso`,
`ses_f0b7cc1d7ffeCGr09SeDRJRjgG`; [timeout investigation](../timeout-investigation.md).

### C. Parallel work outpaced integration and durable checkpointing

The first broad civilisation run made **13 task calls across 11 subagents** before
its usage-limit interruption. Twelve calls completed; an integration call failed.
New broad economic/combat/relic work was opened while earlier integration was
unfinished. Only two implementation commits had shipped, and neither Britons nor
Franks was yet complete to the agreed checklist.

Unintegrated worktrees/patches were in `/tmp/opencode`. The directory was empty
when work resumed; only work already transferred to main survived. A narrower
monastery implementation had to be reconstructed. Moving worktrees into `.local`
then caused Vitest to collect sibling tests: a retained gate shows 130 files,
1,709 tests and five failures. Test discovery exclusions were added afterwards.

The lesson is not that delegation failed universally. Bounded source audits and
isolated implementations were useful. The failure was **unbounded unfinished
integration plus ephemeral storage**. Later civilisation-by-civilisation commits
were clearer. Interactive work nevertheless accumulated again into 42-file and
44-file checkpoints (`60d37b4`, `5be3f31`). These were disclosed and user-approved
checkpoints, but made independent regression attribution harder.

### D. Shared-play acceptance did not include deployment compatibility

Initial shared tests used `structuredClone`, while clients crossed JSON. Dropped
undefined properties and different property insertion order caused false checksum
mismatches. Full presentation rebuilds amplified them into severe stutter. A human
save reproduced divergence after 318 ticks. Wire-codec tests and canonical object
hashing repaired the actual chain (#153).

Later, Regicide correctly introduced shared protocol v2. The managed host retained
v1 code in memory while serving v2 frontend files from mutable main. Private
matching-host tests passed, but deployed fresh/reloaded clients rejected the
version mismatch. #241 remains open at the endpoint; the handoff preserves the
old live state because no verified export/migration exists.

**Analysis:** preserving the process was prudent once the problem existed, but
it is not the same as preserving usable shared play. Protocol acceptance must
include an operational upgrade/preservation path, and the frontend/runtime should
not advance independently. A clean gate cannot establish that by itself.

### E. Resource costs were repeatedly discovered after expansion

The x2 import retained eager-loading assumptions until the browser step failed.
Linux's apparent disk capacity also concealed the Windows backing drive's low
headroom. Separate machine-check/SIGBUS incidents exist; they cannot all be
attributed to sprites or storage from the surviving evidence.

A shared-host checkpoint mismatch then caused thousands of automatic restarts
while startup reporting missed the service. Exit policy and managed-service
reporting fixed that (#155/#157/#158). #157 and #158 were duplicate investigations
of one failure, not two delivered fixes.

Atlas caching remains costly despite being a prior review priority. The RGB565
change invalidated all 3,162 groups, including 1,640 mask groups independent of
that arithmetic. Adding Chinese changed canonical paths for existing assets and
caused unrelated art to decode again. #257 records both defects. The Chinese
import took roughly 80 minutes, but new art also needed conversion: the avoidable
share has not been isolated by timing and should not be invented.

Gate cost itself grew. The latest run spent 556 seconds in npm tests and 433 in
Python tests. Removing a redundant 19 GB asset copy cut the recorded build from
11m38s in an earlier checkpoint to seconds, but an asset-inclusive build remains
unresolved (#255). Expensive checks should be scheduled deliberately; weakening
acceptance is not an optimisation.

### F. Unchanged timeouts concealed a reduction in acceptance scope

`508a2f2` changed the AI test “builds what the new age opened rather than fighting
on with militia” to begin at **`age: 1`**. After corrected map spacing, the earlier
Dark-Age-start scenario reached Feudal but failed to build a range within six
minutes. The behavior was honestly recorded on #124, and isolated component tests
can reasonably start at the unlock. But that does not preserve the earlier
integrated progression guarantee.

Reports emphasised unchanged clocks while omitting this reduced scope. A report
must name altered prerequisites, staged resources/ages and removed assertions,
not only widened timeouts. Most other sampled fixture changes were legitimate
source-aware maintenance; they should not all be classified as weakened tests.

### G. Native fidelity and human approval were occasionally overstated

`4ba51db` called the provisional conversion inheritance rule “User-approved
policy.” The user authorised implementation, not that specific claim of native
correctness. The attribution was later corrected. Owned Loom and combat outcomes
proved internal behavior, not unmeasured conversion exceptions.

The endpoint is generally more careful. Gothic death-spawn/population semantics,
Teuton zero-time activation, Japanese charge/packing, and Chinese volley/alternate
weapon/rounding policies remain explicitly tracked (#252–254, #259–260). They
affect gameplay, not merely visual polish. “Playable scoped completion” is fair;
“complete DE fidelity” is not.

## 5. Human and agent working patterns

The highest-value human input was concrete: reference captures with settings,
precise visible symptoms, an evolved shared save, exact cargo behavior, and clear
scope consolidation. These repeatedly disproved assumptions that had already
passed our tests. The #58 formal-review request caught destructive lifecycle
behavior before commit. The correction from generic sheep-following to AI orders
prevented repeating an earlier invented rule.

The agent improved in retaining failed receipts, separating measured outcomes from
native semantics, asking before an unsupported rule, and reporting unfinished
work. It still accepted broad time-based mandates without a credible integrated
throughput/resource budget, opened too much parallel work, and relied on the human
to discover stalls or challenge an incorrect acceptance oracle.

A 53-civilisation mandate should have been translated into a measured first-civ
vertical slice, then an evidence-based capacity estimate. The human's authorisation
to use parallel agents did not require opening every dependency family at once.
The exact account quota was not known; any claim that a simple quota check would
have guaranteed the full run would exceed the evidence.

## 6. Prioritised corrective actions

These are proposed changes, not implemented by this review.

1. **Restore operational shared compatibility (#241).** Preserve/export the old
   state, privately verify migration and continuation, then coordinate a compatible
   runtime/frontend release. Acceptance: an evolved saved match plus two real
   clients survives the upgrade without reset, unintended resync or lost queues.
2. **Make acceptance independent and durable (#263).** For each feature, name the
   reported symptom, expected native/user behavior and outcome check before
   implementation. Maintain a change-to-browser-scenario registry with receipts
   tied to code/assets. Use appropriate tiers for expensive soaks. Report reduced
   preconditions/assertions, and restore an explicit integrated AI progression
   scenario alongside component tests (#124).
3. **Verify safeguards in the active harness (#262).** Test actual rejection of
   stale-gate commits and prohibited waits in an isolated repository, rather than
   infer enforcement from Claude-only hooks or permission configuration. Keep the
   current provider deadline; add supervised progress/deadline accounting for
   unattended runs. Test stalled requests, retry exhaustion and healthy long jobs
   separately. A run should report a blocked state rather than consume the night
   silently.
4. **Limit unfinished integration.** Keep implementation worktrees in persistent
   ignored storage with tested discovery exclusions. Prefer one integrating slice
   plus one bounded independent research task; expand only after measured benefit.
   Checkpoint and verify the first complete civilisation before opening more
   cross-cutting families. Acceptance is recoverability after interruption, not
   merely successful task spawning.
5. **Fix cache identity/dependency invalidation (#257).** Separate source/layer
   identity from canonical publication paths and decode fingerprints by real
   dependencies. Measure warm-import reuse across a new civilisation and a
   main-layer-only decoder correction, retaining byte-identical outputs.
6. **Prune status and narrow claims (#264).** Keep current state concise, link
   historical receipts, and make stale-check coverage explicit. A fresh session
   must not receive mutually contradictory answers about delivered features.

## 7. Limits and conclusion

No defensible aggregate token-cost or total-wasted-hours figure can be produced
from this audit. Timed approval/provider stalls are established; all import time,
gate failures, quota gaps and investigation windows cannot be added together and
called waste. Nor were all historic gates replayed or every reported bug newly
reproduced. Current #258 is a human-filed open symptom, not a newly verified
root cause in this review.

**The period's progress is real. Its strongest improvement is that outcome
checks, failure records and honest limits became normal. Its weakest point is
that the agent still too often supplies both the implementation and the definition
of success, while the human supplies the independent correction afterwards.**
The next improvement should be reliable acceptance, recovery and deployment around
the existing feature pipeline—not another layer of prose promising to be careful.

The subsequent implementation pass passively rechecked the live endpoint: the
September30 reboot had already brought the host to protocol2. The September26–27
host-v1/frontend-v2 observation above remains valid historical evidence, but was
not a fresh measurement of the endpoint at this review's handoff. The current
join failure had an additional cause: the Artemis gateway still hardcoded
version1. A real two-browser run reproduced that failure; forwarding the host
version corrected it. The review should have refreshed the deployment measurement
instead of relying on the dated handoff for current operational state.

The owner then explicitly confirmed no match needed preservation, permitting a
fresh deployment with pinned application code/JSON and a corrected gateway.
